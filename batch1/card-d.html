Infrastructure & Operations — After supply: how the endpoint actually runs inside a machine.

Detailed explanation

1. The data lane

  • End customers, interfaces NIC, drivers implement, kernel stack, net device, TCP/IP.
  • Computer, storage, hardware, OEM, mounted file system, driven by software for fast trading and communication.
  • Switch to transport, router to private IP, NIC to public IP.

2. How the device is built inside

  • Device emulation, core functions, business, ASIC hardware, shared component, libraries (firmware), port to business to network to customer.
  • Network device, hardware plus software, OEM, network hierarchy, organisation business network, product plus custom.

3. The management lane, separate

  • OOB, BMC / IDC / ILO, sbin / init (power), switch, network switch; options, CLI, sbin to router, IP route, web, Nginx / Apache, DNS book, switch, API / communication / restful / netconf, proc / sys.
  • Root to OOB, sbin / init to BMC (power), to CLI admin, IP / route / device / config files to start; etc config, startup.config.
  • OOB to BMC / IDRC / ILO to API, web UI, CLI / router, running config, proc / sys, start up to hardware.
  • The two lanes must not be confused. The data lane goes customer, interface, driver, kernel, net device, TCP/IP. The management lane sits beside it: out-of-band to BMC, then CLI, web or API, and it works even when the data lane does not.
  • Learning them as two lanes explains why a device can be managed while it is down.

Summary:

  • Data lane and management lane are two lanes, not one stack.
  • The data lane carries traffic; the management lane manages the device.
  • A device can be managed while it is down, because the management lane is separate.
